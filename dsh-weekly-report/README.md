**装上即用的 DSH 完整插件**：双击即装，自动注册 bundle、自动常驻面板服务、自动打开面板，全程不用敲命令。API Key、输出目录、绩效表与模板由使用者按需提供，插件负责识别并据此生成、输出。

> 使用者手册：[`操作使用手册.html`](./操作使用手册.html)（单页、导航 + 搜索 + 一键复制）。本文是维护者速览。

## 双击即装（零命令）

| 系统 | 双击这个 | 效果 |
|---|---|---|
| Windows | **`一键安装.vbs`**（首选） | 隐藏窗口自动定位 Node → 执行安装 → 打开中文面板；成功不弹窗，失败才给诊断 |
| Windows | `一键安装.cmd`（备用） | VBS 被安全策略拦掉时的替代；控制台显示进度，装完自动开面板 |
| macOS | **`一键安装.command`** | 自动定位 Node → 安装 → 打开面板 → 按回车关闭 |
| Linux | `bash install.sh` | 同上 |

安装器自动完成：定位 Node（DSH 自带 / WorkBuddy / 系统 / PATH）→ 把插件注册进 DSH profile（`node_modules` 链接 + `dsh.profile.bundles` + `cordis.patch.yml`）→ 写入兼容转发 → 确保绩效表组件 → 启动面板服务 → 打开浏览器。**不需要命令行、不需要重启 DSH、不需要二次补装。**

### 为什么还要「双击」这一次

安装动作本身要改三个地方：`<profile>/node_modules` 里的链接、`<profile>/package.json` 的 bundle 依赖、`cordis.patch.yml` 的 insert 块。这三处都在 DSH 的配置目录里，**必须由一个本地进程去写**，DSH 运行时不会去扫描任意目录并把插件挂上来。所以「零操作」在工程上只能是：

1. **双击一次**（本包的默认路径，双击只是触发器，不要求用户敲命令）；
2. 或者从 DSH 的插件页添加本目录 —— Host 半身会自动自举数据目录、面板服务与组件（`lib/index.js` 里的 `bootstrap()`），效果与安装器一致；
3. 或者命令行 `node install.mjs`。

环境依赖只有三条：**Node ≥ 20**（DSH 自带，安装器会自动找到）、**本机 DSH profile 目录可写**、**Windows/macOS/Linux 任一**。不需要联网，不需要 npm 安装（绩效表组件已随包自带）。

> Windows 的 `.vbs` / `.cmd` 刻意写成纯 ASCII：WSH 与 cmd 都按系统代码页读脚本，中文会乱码；界面提示都落在自动打开的中文面板里。安装结果摘要写进 `.install-result.tmp`（纯 ASCII），仅在失败时用于诊断，成功后自动删除。也支持 `node install.mjs --open --result-file <path>` 手动调用。

**不用重启 DSH**：新服务沿用旧版的文件名 `service/server.cjs` 与端口 `8798`，DSH 侧边栏 iframe 指向不变，安装完成立刻能看到新界面。若侧边栏没刷新，点一下面板里的刷新即可。

> **兼容转发是怎么做到免重启的**：DSH 里已加载的旧版 Host 半身，内存中的路径仍指向旧插件目录，每 20 秒会按旧路径拉起面板服务；而从终端启动的常驻进程会随会话结束被清理，端口会被旧服务抢回去。安装器因此把旧路径的 `server.cjs` **备份后换成一行转发**（`require('<新包>/service/server.cjs')`），DSH 心跳拉起的进程就直接执行新包的服务 —— 进程归 DSH 进程树所有，稳定常驻，既不用重启 DSH，也不用装计划任务。旧插件的引擎、UI、配置全部没动，`--uninstall` 会把原文件完整恢复。

| 命令 | 用途 |
|---|---|
| `node install.mjs` | 等价于双击（不自动开浏览器） |
| `node install.mjs --open` | 装完自动打开面板 |
| `node install.mjs --dry-run` | 预览改动，不写任何文件 |
| `node install.mjs --verify` | 校验 9 项安装状态 |
| `node install.mjs --uninstall` | 一键回滚（保留使用者数据） |
| `node install.mjs --profile=web` | 装到指定 profile |
| `node install.mjs --json` | 机器可读输出 |
| `npm run repair` | 检查并修复历史周报里被切断的记录 |
| `npm run setup` / `verify` / `uninstall` | 等价快捷方式 |

面板地址：`http://127.0.0.1:8798/`，也可以直接在浏览器打开。

## 是不是「完全插件化、装完即用」

**是。** 本包是完整的 DSH 插件：`package.json` 声明 `dsh.bundle` / `dsh.client`，含 Host 半身（保活）、浏览器半身（侧边栏入口）、本地面板服务、周报生成引擎和面板网页，不依赖桌面脚本、Python 或外部服务。**双击 `一键安装.vbs` 即完成全部动作并自动打开面板**，装完侧边栏直接可用，无需重启 DSH。

三点边界说清楚：

| 事项 | 实际情况 |
|---|---|
| 安装动作 | 双击一次即可，无命令行输入。若从 DSH 插件页填目录/仓库安装，Host 半身会自举数据目录、面板服务与绩效表组件，能力一致。 |
| 绩效表组件 | **完整分发包自带 `node_modules/exceljs`，零网络、零补装**。只有用户主动精简掉 `node_modules` 时才需要补装 —— 已由安装器与设置页按钮自动完成，不再依赖 PATH 里的 npm。 |
| 需要使用者提供 | API Key、处理人、输出目录、绩效表目录与模板 —— 这是数据，不是插件不完整。 |

`node install.mjs --verify` 可随时自检（当前 9/9 全绿）。

## 装完之后只需三件事

1. **设置 → 研发平台接入**：粘贴你的 API Key（工单数据来源），填处理人姓名，可点「测试连接」验证。
2. **设置 → 输出与模板**：填周报输出目录；需要绩效表时再填绩效表目录（放入月度考核表 .xlsx）；模板不改就沿用约定格式。
3. **生成**：选本周 / 上周 / 本月 / 自定义区间，点「开始生成」。

邮件通知**默认关闭**、SMTP 全空，插件不预置任何凭据。概览页的「准备情况」会把还缺什么直接说清楚。

## 口径与约定

本包在开发期参考了 DeepSeek Harness 的历史会话索引（仅用于确定规则与偏好，**运行时不读取会话内容**）。沿用下来的约定：

| 约定 | 内容 | 落实位置 |
|---|---|---|
| 周报块格式 | `【类别】/ 学校 / 时间 / 事项 / 工作内容 / 重要说明 / 进度`；每周六 12:00 | `service/engine/templates/周报模板.txt`、`render.mjs` |
| 绩效表口径 | 本月全部周报内容、时间一致、**格式保持不能改变**；每周生成时导入，月底复核 | `--perf-auto` / `--perf-check`，`perf.mjs` 只改明细行 |
| 界面偏好 | 美观简洁、方便查看内容与引用/附件 | 全新 `service/public/` 四页轻界面 + 历史页全文预览 |
| 稳定性 | 不允许「识别不到 / 面板失败」 | 安装自动注册、`/api/ping` 轻量保活、兼容旧 host 半身 |
| 常驻方式 | 保持在线、不打扰 | 20 秒心跳静默拉起，`windowsHide` 无窗口，不装计划任务 |

## 架构

```
DSH 侧边栏「周报」
   └─ iframe → http://127.0.0.1:8798/        ← service/server.cjs（Node 标准库）
                 ├─ service/public/          全新面板 UI（原生 HTML/CSS/JS）
                 ├─ service/paths.cjs        数据目录 / 配置 / 模板 / 历史
                 ├─ service/engine/         gen-weekly.mjs + lib/*.mjs（工单采集 / 渲染 / 绩效表）
                 └─ <data>/                 %USERPROFILE%\.dsh\weekly-report\
                       config.json / api-key.txt / reports/ / logs/
```

- `lib/index.js`：DSH Host 半身，20 秒探活、挂了静默拉起。
- `lib/client.js`：浏览器半身，侧边栏入口 + 在线状态点。
- `plugin.json`：机器可读能力清单（安装方式、配置边界、格式与规则）。

## 面板交互与尺寸适配

- **统一展开/收起**：运行日志、生成结果「查看内容 / 收起内容」、周报全文、组件补装 / 月底复核输出、概览的周报格式预览，共 5 处都带状态按钮，按钮文案随状态切换，收起后不占空间。
- **自动匹配页面尺寸**：`100dvh` 三段式布局（顶栏 / 导航 / 主内容区自滚），所有日志、预览、弹窗高度用 `clamp()` + `dvh` 按视口计算；在 DSH 侧边栏 iframe 里也会按 iframe 实际高度适配，不出现双滚动条。
- **历史周报查找**：左侧列表按视口高度自适应并内部上下滚动，搜索框吸顶、显示「共 N 份 / 显示 M 份」；右侧全文独立滚动，内容多时不会把页面撑长。
- **消除留白**：移除固定 `min-height:440px` 与空态 `padding-top:150px`，空态改为 flex 居中；卡片间距、矮屏（≤760px）与窄屏（≤980px）分别收紧。

## 数据正确性与交互修复（本轮）

| 现象 | 根因 | 修复 |
|---|---|---|
| 周报里一条记录「学校 / 项目」为空 | 该任务无 `school_name`，`splitSchool` 也推不出校名，`{{school}}` 渲染成空行；周报条目又用空行分隔，于是一条记录被切成两段 | `rules.mjs` 用 `resolveSchool()` 多级兜底（校名 → 标题推断 → 产品 → 标题首段 → 通用事项）；`render.mjs` 再把所有字段压成单行并清掉模板空行，双保险。历史文件由 `repair-report.mjs` 按 `【类别】` 行重新分块合并，已在历史页提供「检查格式」入口，写前备份、正常文件幂等不重写 |
| 右上角「打开数据目录」及所有打开目录按钮无反应 | 后端 `execFile('explorer.exe', ..., () => {})` 把异步错误整个吞掉，永远返回 `ok:true`；前端三处又是 `void post(...)` 不看结果 | 改用 `WINDIR` 绝对路径 + `spawn`，预检路径存在性、监听 `error`、返回真实结果；传文件路径时用 `/select,` 直接选中；前端统一 `openPath()` 给 toast，失败自动复制路径兜底 |
| 概览「周报格式」像是写死的 | 预览用的是 `builtinText`（内置模板），字段值全是固定示例词 | 改用**当前生效模板**渲染，明确标注「示例值」，说明学校/项目/事项/时间/进度都由工单数据填充；新增「看真实数据」切换到最近一份周报的首条记录；保存模板后实时刷新 |

**「打开数据目录」的功能点**：打开 `%USERPROFILE%\.dsh\weekly-report\`，里面是 `config.json`（配置）、`api-key.txt`、周报输出与运行日志 —— 用于查看、备份或排查，不会修改任何内容。

## 绩效表：结构识别 + 只改目标格（v1.1.0 重做）

使用者反馈「绩效表结构被改了」，根因是旧实现把版式写死（B/D/J/K/L/M、明细固定第 7 行），并且**每写一次就先把整块六列清空再重写**，还统一覆盖字体、强行改日期格式；条目超过可写行数时还会插行下移考核区块。

现在改成：

| 环节 | 做法 |
|---|---|
| 认版式 | `service/engine/lib/perf-map.mjs` 按**表头文字**找列（类别/任务名称/开始时间/结束时间/是否完成/评定），按「工作任务考核」区块标题算可写行数，「被考评人/考评时间/填报时间」也按标签找右侧单元格；认不出的字段退回默认列并在面板里标出来 |
| 写入 | 只改真正需要变的格子：值相同就跳过；已有内容的格子只改值不动样式；**不再清空整块、不再统一覆盖字体**；日期格式沿用模板该列已有格式 |
| 结构 | 写前写后各取一次结构指纹（总行数、列数、合并区数量与位置、考核区块行），有变化会在结果里如实报告，不再偷偷改 |
| 行数不够 | **默认不插行**，只提示「本月 N 条、可写 M 行，超出部分未写入」；确实要扩展行时在设置里勾「允许自动扩展行」 |
| 备份 | 每次就地写入前，把原表复制到同目录 `.perf-backup\<文件名>.<时间戳>.xlsx`，只留最近 8 份 |
| 使用者模板 | 设置页「绩效表模板」可指定任意一张 xlsx；留空则用当月的表或目录里最新的表。旁边的「检测表格结构」不写任何文件，把识别结果（哪列、哪几行、哪个格子）摊开给人核对 |

命令行也可以单独看：`node service/engine/gen-weekly.mjs --config <cfg> --perf-layout <xlsx>`。
生成时加 `--perf-preview` 只预览「将会改动哪些单元格」，不落盘。

## 周报时间口径（本周未完成 → 开始时间 ~ 本周周日）

旧版把未完成事项的结束时间拉到「统计区间末尾」，周报里出现过 `11月9日-30日` 这种越过本周的写法。

现在的口径固定为：

- **已完成**：开始时间 ~ 实际完成时间；同一天则只写一天；
- **未完成**：开始时间 ~ **本周周日**（本周一算起点，周日为结束），且任何一条的结束时间都不许越过本周周日；
- 开始时早于本周的，起点收在本周一（周报只记本周发生的事）。

三处同时生效：`gen-weekly.mjs` 的 `itemsOfWeek`（含「本周新建但还没记工时」的分支）、末尾兜底裁剪、以及 `perf.mjs` 的 `itemsToPerfRows`（写绩效表时同样按周口径，不再写月末）。

## 数据来源边界

- **运行时数据源**：研发平台 MCP 的工单 / 任务 / 工时（需使用者提供 API Key）。
- **会话数据**：仅作为开发期设计参考，插件运行期间不读取 `~/.dsh/sessions`，也不读取 WorkBuddy 会话。
- **零凭据**：包内不含 API Key、SMTP 授权码、任何本机绝对路径或个人信息。

## 依赖

| 功能 | 依赖 |
|---|---|
| 周报 txt 生成、模板、历史、面板 | **零第三方依赖**，Node ≥ 20 标准库 |
| 绩效表 .xlsx 写入 / 月底复核 | `exceljs@4.4.0`（可选），设置页「补装绩效表组件」一键安装；未安装时明确提示，不影响周报主功能 |

**完整分发包保留 `node_modules/`（内含 `exceljs` 及其依赖），绩效表写入与月底复核零网络开箱可用**，不需要点任何补装按钮。若为了减小体积主动删掉它，安装器与设置页「检测 / 补装组件」会自动补回。

补装失败曾复现为 `'node' 不是内部或外部命令`：面板服务由 DSH 内置 Node 启动，那个目录只有 `node.exe`、没有 npm，而旧实现用 `npm.cmd + shell` 依赖 PATH。现已改为 `service/perf-deps.cjs` 统一处理：

- 组件已自带就**直接短路**，绝不重复安装；
- 真需要装时，用当前 Node 的绝对路径直调 `npm-cli.js`，并把 node 目录注入子进程 PATH，不经 shell / `.cmd`；
- 带 `error` 监听、150 秒超时、可读中文原因与手动命令，绝不抛未捕获异常拖垮面板服务；
- 面板输出区带状态与「收起输出」，失败时给出可复制的手动命令。
