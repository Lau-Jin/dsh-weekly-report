# 周报工作台 · dsh-weekly-report v1.5.0

**装上即用的 DSH 插件**：自动注册 bundle、自动常驻面板服务、自动打开面板，全程不用敲命令。
使用者提供 API Key、输出目录、绩效表与模板，插件负责识别并据此生成周报与绩效表。

> 使用者手册：[`操作使用手册.html`](./操作使用手册.html)（单页、导航 + 搜索 + 一键复制）。

## 安装

本插件通过 npm 发布，**安装、升级、卸载只走标准流程**，不需要任何本地安装器或脚本：

1. 在 DSH 的 profile 目录（`%USERPROFILE%\.dsh\profiles\desktop`）执行：
   ```bash
   pnpm add dsh-weekly-report-lau
   ```
   或编辑 `package.json` 的 `dependencies` 加入 `"dsh-weekly-report-lau": "^1.5.0"` 后 `pnpm install`。
2. bundle 由包内 `cordis.patch.yml` 自动挂载；宿主心跳每 20 秒保活、挂了自动拉起；面板地址 `http://127.0.0.1:8798/`。
3. **不需要重启 DSH**：新包就位后，宿主下一次心跳（≤20 秒）即拉起新版本面板。

环境依赖只有两条：**Node ≥ 20**（DSH 自带）、**本机 DSH profile 目录可写**；不需要 Python 或外部服务。

| 命令 | 用途 |
|---|---|
| `pnpm add dsh-weekly-report-lau` | 安装 / 升级到最新版 |
| `pnpm remove dsh-weekly-report-lau` | 卸载，使用者数据（`%USERPROFILE%\.dsh\weekly-report\`）完整保留 |
| `npm run repair` | 检查并修复历史周报里被切断的记录 |

## 装完之后只需三件事

1. **设置 → 研发平台接入**：粘贴 API Key（工单数据来源），填处理人姓名，可点「测试连接」验证。
2. **设置 → 输出与模板**：填周报输出目录；需要绩效表时再填绩效表目录（放入月度考核表 .xlsx）。
3. **生成**：选本周 / 上周 / 上个月 / 自定义区间，点「开始生成」。

邮件通知**默认关闭**、SMTP 全空，插件不预置任何凭据。概览页的「准备情况」会把还缺什么直接说清楚。

## 口径与约定

本包在开发期参考了 DeepSeek Harness 的历史会话索引（仅用于确定规则与偏好，**运行时不读取会话内容**）。

| 约定 | 内容 |
|---|---|
| 周报块格式 | `【类别】/ 学校 / 时间 / 事项 / 工作内容 / 重要说明 / 进度` |
| 绩效表口径 | 本月全部周报内容、时间一致、**格式保持不能改变**；每周生成时导入，月底复核 |
| 界面偏好 | 美观简洁、方便查看内容与引用/附件（概览 / 生成 / 设置 / 历史 四页） |
| 稳定性 | 不允许「识别不到 / 面板失败」；20 秒心跳静默拉起、无窗口、不装计划任务 |

## 周报时间口径

- **已完成**：开始时间 ~ 实际完成时间；同一天则只写一天。
- **未完成**：开始时间 ~ **本周周日**，任何一条的结束时间都不许越过本周周日。
- 开始时早于本周的，起点收在本周一（周报只记本周发生的事）。
- **补创工单**：工时日期早于工单创建日期时，起点以工时日期为准（例：11/9 建单、工时填 11/6 → 起点 11/6）。
- **未完成工单逐周叠加**：只要工单未完成、未取消，生成跨度内**每一周**都要列出它，起点固定、终点逐周推进到本周日；完成当周取实际完成日，之后不再出现；取消后不产出。

## 周报周期与绩效表口径

- **周报按完整的自然周（周一 ~ 周日）生成**，不按月份切、也不裁剪到所选区间：
  选 10/1~10/31 → 出 5 份：`9/28~10/4`、`10/5~10/11`、`10/12~10/18`、`10/19~10/25`、`10/26~11/1`；
  选 9/28~10/4 → 就出这一整周。
- **绩效表按「包含该月的周报」取数**：跨月的那一周，两个月各取自己那段
  （`9/28~10/4` 的记录进 9 月与 10 月，`10/26~11/1` 的进 10 月与 11 月），
  时间落在本月的才写进本月的表。
- **没完成的工单会逐周延续**（时间一直延到本周日），所以它会自然出现在后续月份的表里；
  等它完成时，月底核对会把完成标记与时间**矫正**回来，两边数据对齐。
- **月底最终核对不等最后一份周报**：月末最后几天（例如 11/30 是周一，它那周要到 12/6 才出周报）
  所属的周还没生成时，插件会**直接按整月拉平台数据补齐**，保证月底的表当天就能核全；
  那份跨月周之后再生成时，它与本月的交集会再合并一次。

## 工单归属判定（严格模式，测试版）

平台按权限返回工单，搜出来的列表里混着「我可见但不是我干的」工单。设置里打开
**「严格归属判定」**后，判定口径如下（默认关闭，保持原行为）：

| 信号 | 来源 | 判定 |
|---|---|---|
| 本人在该任务上有工时 | 工时记录人（按 user id 精确比对） | **计入**（真干过） |
| 处理人是本人 | 工单的处理人字段 | **计入** |
| 创建人是本人，但处理人不是本人、也没本人工时 | 工单的创建人字段 | **剔除**（只是报障/提单） |
| 本人只是协办人、且没有本人工时 | 工单详情的协办人 | **剔除**（挂名） |
| 与本人完全无关 | — | **剔除**（纯权限可见） |
| 工单已取消 | 工单状态 | **剔除** |

代别人出周报时（目标处理人 ≠ 账号本人）：账号自己的工时**不算**目标的，
插件会按任务查「所有人」的工时（`task_list_task_worklogs`），确认目标本人是否真干过；
处理人是目标、或目标本人确实有工时，才计入。

## 绩效表写入规则

- 版式按**表头文字**自动识别（类别 / 任务名称 / 开始时间 / 结束时间 / 是否完成 / 评定），不写死列号。
- **只改需要变的格子**：值相同跳过；不清空整块、不覆盖字体、不强行改日期格式。
- 写前写后各取一次结构指纹，有变化如实报告；就地写入前自动备份（保留最近 8 份）。
- 明细区写满时**自动下移考核区块插行**（条目不丢、样式与区块不动）；不想改结构可在设置里关掉「允许自动扩展行」。
- 模板版式认不出来时**拒绝写入**并提示用「检测表格结构」核对 —— 不会把模板标题写空、把布局打乱。
- 设置页「绩效表模板」可指定任意 xlsx；留空则用当月的表或目录里最新的表。旁边的「检测表格结构」不写任何文件，把识别结果（哪列、哪几行、哪个格子）摊开给人核对。
- **生成时会补齐缺失的历史绩效表**：只要某个月有周报、目录里却没有对应的表，就按周报内容建一张并核对；
  同一个月反复同步只写同一张表，不会每次新建。

## 数据来源边界

- **运行时数据源**：研发平台 MCP 的工单 / 任务 / 工时（需使用者提供 API Key）。
- **会话数据**：仅作为开发期设计参考，插件运行期间不读取 `~/.dsh/sessions`，也不读取 WorkBuddy 会话。
- **零凭据**：包内不含 API Key、SMTP 授权码、任何本机绝对路径或个人信息。

## 依赖

| 功能 | 依赖 |
|---|---|
| 周报 txt 生成、模板、历史、面板 | **零第三方依赖**，Node ≥ 20 标准库 |
| 绩效表 .xlsx 写入 / 月底复核 | `exceljs@4.4.0`，以 `bundledDependencies` 打进 npm 包，安装与更新都会随包带上，开箱可用 |

## 版本回退（面板里点一下）

设置页底部有「**版本与回退**」卡片：

1. 点「刷新版本列表」→ 面板去 npm registry 查已发布版本，下拉里直接选；
2. 点「回退到该版本」→ 二次确认后开始执行，右侧实时输出日志；
3. 回退期间面板会短暂断开（插件目录被替换），完成后**重启一次 DSH** 即可。

原理与发布工具同一套：占位应答器接管面板端口 → 结束面板进程让目录解锁 →
`pnpm` 按精确版本安装 → 撤占位器 → 心跳自动拉起新版本面板。
周报、绩效表与配置都不会被动（数据在 `~/.dsh/weekly-report`，与插件目录分开）。

## 安全与回滚

- 服务只监听 `127.0.0.1`；周报读取限制在输出目录内，静态资源防目录穿越。
- 配置 / Key 写前自动备份，损坏文件另存 `.corrupt` 不静默覆盖。
- 卸载（DSH 插件页，或 `pnpm remove dsh-weekly-report-lau`）后使用者数据完整保留。
- 索引与配置可能包含个人信息，**不要把数据目录打包分享**。
