Weekly Report Studio

装上，就能用

一条命令完成安装与启动，不用重启 DSH、不用手工拉服务。API Key、输出目录、绩效表与模板由你按需提供，插件负责识别并据此生成、输出。

1 · 开始之前

项目要求
运行环境Node ≥ 20（DSH 自带，一般无需另装）
核心功能依赖零第三方依赖。周报 txt 生成、模板、历史、面板全部用 Node 标准库
可选依赖exceljs@4.4.0，仅「写入绩效表 .xlsx」需要。完整分发包已自带（保留 node_modules/），零网络开箱可用；精简包才需自动补装
需要你提供研发平台 API Key、处理人姓名、周报输出目录；绩效表目录与自定义模板按需
不需要不需要联网安装依赖、不需要装 Python、不需要计划任务、不需要重启 DSH
本插件在开发时参考了 DeepSeek Harness 的历史会话，用来确定周报格式、绩效表规则与界面偏好；运行期间不会读取任何会话内容。数据来源只有研发平台的工单与任务。

2 · 一键安装

推荐：双击即装，全程不用敲命令。

系统双击 / 运行效果
Windows一键安装.vbs（首选）隐藏窗口自动定位 Node → 安装 → 打开中文面板；成功不弹窗，失败才给诊断
Windows一键安装.cmd（备用）VBS 被安全策略拦掉时用；控制台显示进度，装完自动开面板
macOS一键安装.command安装 → 打开面板 → 按回车关闭
Linuxbash install.sh安装 → 打开面板

也可以手动执行：

node install.mjs

安装器自动完成：定位 Node → 注册插件到 DSH profile → 确保 cordis.patch.yml 的 bundle 声明 → 写入兼容转发 → 确保绩效表组件 → 启动面板服务。加 --open 可让命令方式也自动打开浏览器。

为什么还要「双击」这一次：安装要改三处 DSH 配置（profile 里的 node_modules 链接、package.json 的 bundle 依赖、cordis.patch.yml 的 insert 块），必须由本机进程去写，DSH 运行时不会扫描任意目录把插件挂上来。双击只是触发器，不需要敲命令。环境依赖只有三条：Node ≥ 20（DSH 自带）、profile 目录可写、Windows/macOS/Linux 任一；不需要联网，也不需要 npm 安装。
命令用途
node install.mjs --dry-run预览改动，不写任何文件
node install.mjs --verify校验 9 项安装状态
node install.mjs --uninstall一键回滚，保留使用者数据
node install.mjs --profile=web装到指定 profile（默认 desktop）
node install.mjs --json机器可读输出，便于脚本集成
重复运行是幂等的：已装好会显示「已是最新」，不会重复写配置或覆盖你的其它插件。

3 · 打开面板

装完直接在 DSH 左侧边栏点「周报」。也可以浏览器打开：

http://127.0.0.1:8798/

为什么不用重启 DSH：新服务沿用旧版的文件名 service/server.cjs 和端口 8798，侧边栏 iframe 指向不变，服务一换，界面立刻是新的。若侧边栏没刷新，点面板里的刷新即可。

服务由插件 Host 半身每 20 秒静默探活，挂了会自动拉起（无控制台窗口）；不安装任何计划任务。

右上角「打开数据目录」用于打开 %USERPROFILE%\.dsh\weekly-report\：里面是 config.json（配置）、api-key.txt、周报输出与运行日志，方便查看、备份或排查，点击只打开目录、不修改任何内容。生成结果与历史页的「打开所在目录 / 打开目录」会在资源管理器里直接选中对应周报文件。

面板按当前窗口 / iframe 的实际高度自动排布：顶栏与导航固定，内容区自己滚动。日志、周报全文、组件输出、格式预览都带「收起」按钮；历史周报多时，在左侧列表内上下滚动查找，搜索框始终吸顶并显示总数。所有打开类操作都会给出结果提示，失败时自动复制路径便于手动粘贴。

4 · 首次配置

打开「设置」页，按需要填三项，然后点底部「保存设置」：

  1. 研发平台接入：粘贴 API Key（工单数据来源）、填处理人姓名、确认 MCP 地址。可点「测试连接」看识别出多少工具。
  2. 输出与模板：填周报输出目录；需要绩效表时填绩效表目录（放入月度考核表 .xlsx），必要时再指定一张绩效表模板（留空就用当月的表）。路径可以点「浏览」选择，也可直接粘贴。
  3. 周报模板：不改就沿用你约定的格式；要改可直接编辑占位符，或点「恢复内置」。
概览页的「准备情况」会实时列出还缺什么；就绪度环显示完成项 / 总项数，不用猜哪里没配好。

5 · 生成周报

「生成」页选周期，点「开始生成」；日志实时滚动，结束后直接给出文件路径与内容预览。

周期说明
本周 / 上周按自然周（周一至周日）出一份周报
本月 / 上个月按月拆成若干自然周，每周各出一份
自定义指定起止日期，插件按自然周拆分

可选项：同步写入绩效表（本月全部周报内容）、重新拉取数据（忽略本地缓存）、不含任务中心（只按工单生成）。

没填 API Key 时不会报一堆堆栈，而是提示「请到设置页提供 API Key」；绩效表组件缺失时也会给出明确的补装入口。

6 · 周报格式与模板

沿用你在历史会话里约定的块格式，输出与之前的样例逐字一致：

【项目运维】
×× 学校（示例）
  时间: 2026年11月9日
  事项: 某系统例行巡检（示例事项）
  工作内容：https://example.com/ticket/0000（示例链接）
  重要说明：无
  进度：100%
占位符含义
{{category}}类别，如「项目运维」「交付部署」
{{school}}学校 / 项目名称
{{time}}本周期时间范围，按当前周期填写
{{subject}}事项名称
{{work}}工作内容，通常是工单 / 任务链接
{{note}}重要说明，缺省为「无」
{{progress}}进度百分比

自定义模板保存在数据目录，不改动插件自带文件，方便整包升级。生成习惯：每周六 12:00。

概览页的「周报格式」是不是写死的？不是。它按「设置 → 周报模板」里当前生效的模板渲染，改了模板保存后预览立即跟着变。预览里的学校 / 项目、事项、时间、进度是示例值；实际生成时全部由本周工单与任务数据填充，只有字段名称、顺序和标签由模板决定。点「看真实数据」可切换到最近一份周报的首条记录对照。

7 · 绩效表规则

  • 绩效表内容为本月全部周报内容，时间与周报一致。
  • 格式保持不能改变：只写明细区那六列里该变的格子，其它列（评定说明、工时等）、样式、行高、列宽、合并区、公式、其它工作表全部保持原样。
  • 会认表：按表头文字找列（类别 / 任务名称 / 开始时间 / 结束时间 / 是否完成 / 评定），按「工作任务考核」区块标题算可写行数；「被考评人 / 考评时间 / 填报时间」按标签找右边的格子。换一张版式略有差异的模板也能对上。
  • 先核对再写：设置页「绩效表模板」旁点「检测表格结构」，会把识别结果列出来（哪一列、第几行到第几行、写哪个格子），这一步不写任何文件。
  • 每次写前自动备份：原表复制到同目录 .perf-backup\（保留最近 8 份），写坏了可以直接拿回来。
  • 行数不够不擅自改结构：默认只提示「本月 N 条、可写 M 行」，不会插行移动考核区块；确实需要时在设置里勾「允许自动扩展行」。
  • 每周生成周报时都同步导入绩效表；月底可在「设置」页点「月底内容复核」再核对一次。
  • 写入 .xlsx 需要 exceljs：完整安装包已随包自带，设置页会显示「已就绪 · 随包自带」，点「重新检测组件」也只是确认状态，不会重复安装。若为了减小体积删掉了 node_modules/，点「检测 / 补装组件」会自动装回；输出区可收起，失败时会给出可复制的手动命令。
  • 未装时纯周报 txt 仍可正常生成，不会报堆栈错误。
时间口径：已完成写了开始~实际完成；未完成写开始~本周周日，不会出现「11月9日-30日」这种越过本周的写法。绩效表里的日期用模板该列原有的显示格式，不强行改成别的样式。

8 · 历史与引用内容

「历史」页左边是周报列表（可搜索文件名），右边是全文预览。工作内容里的工单 / 任务链接、重要说明等引用内容都完整保留，可直接查看与「复制全文」。

  • 列表高度按窗口自动计算，文件多时在列表内上下滚动查找，搜索框吸顶、上方显示「共 N 份 / 显示 M 份」。
  • 右侧全文独立滚动；点标题栏的「收起内容」可把全文收起，只留文件名与操作按钮，再点「展开内容」恢复。
  • 生成结果、运行日志、组件输出、概览的格式预览也都有各自的收起按钮。
  • 列表上方的「检查格式」会扫描历史周报，把过去因「学校 / 项目为空」而被切成两段的记录合并回来并补全项目名（原文件自动备份）。正常文件不会被重写。

概览页也展示最近 4 份周报，点一下即可跳到全文。周报按「年月 / 周报_起止日期.txt」归档。

9 · 邮件通知

默认关闭，SMTP 服务器、账号、授权码全部为空，插件不预置任何凭据。需要时在「设置 → 邮件通知」打开开关并填写，保存后生效。

授权码已保存时输入框只显示占位提示，留空表示不修改，不会把掩码写回配置。

10 · 常见问题

现象处理
侧边栏没出现「周报」/ 还是旧界面跑 node install.mjs --verify；确认 cordis.patch.yml 里有 weekly-report 的 insert。刷新面板；若仍不行，完全退出 DSH 再打开一次即可（兼容转发已保证服务是新版本）。
面板打不开先确认 http://127.0.0.1:8798/api/ping 能返回 JSON；服务由 Host 半身每 20 秒自动拉起，也可重跑一次安装。
生成时提示连不上研发平台检查 MCP 地址与 API Key；设置页有「测试连接」。
补装绩效表组件失败旧版会因面板服务环境里没有 npm 而报 'node' 不是内部或外部命令；新版组件已随包自带、按钮直接返回「已自带，无需补装」。若确实精简过包，按钮会用 Node 绝对路径自动安装，失败时输出区会给出可复制的手动命令。
内容展示太长 / 找不到周报文件每块内容都有「收起」；历史列表内部滚动 + 顶部搜索 + 总数提示，页面按窗口高度自动适配。
周报里有一条记录没有学校 / 项目老数据里个别任务没带校名，会把一条记录切成两段。新生成已加多级兜底；历史文件点「历史 → 检查格式」一键合并补全，或执行 npm run repair。
点「打开数据目录 / 打开目录」没反应v1.1.0 已修：根因是启动资源管理器时带了「隐藏窗口」标志，进程起来了但窗口不可见。现在改为可见方式启动，失败会复制路径供手动粘贴。
周报里出现「11月9日-30日」这类越界时间v1.1.0 起未完成事项一律写到本周周日，且任何一条都不越过本周。若看到旧文件，重新生成一次即可。
担心绩效表被改动「设置 → 绩效表模板 → 检测表格结构」先看要写哪些格子；每次写入前原表自动备份到同目录 .perf-backup\，直接复制回来就能还原。默认不会插行移动考核区块。
端口被别的程序占用设置环境变量 WEEKLY_PANEL_PORT 换端口，同步修改侧边栏的面板地址。
换电脑 / 分发给同事整个插件目录拷过去，在那台机器跑一次 node install.mjs；数据目录各自独立，不会带走过任何凭据。

11 · 卸载与回滚

node install.mjs --uninstall

会恢复原来的 node_modules 链接、package.json 依赖与 bundle 清单、旧版 service/server.cjs，并移除安装器自动插入的配置块。使用者数据目录（配置、Key、历史周报、日志）完整保留，不删除任何文件。

安装时对 package.json、cordis.patch.yml、config.json 都做了时间戳备份；原插件链接与旧 server.cjs 会被挪到数据目录的 backups/ 而不是直接删掉。

12 · 安全说明

  • 面板服务只监听 127.0.0.1，不对外暴露。
  • 周报读取限制在输出目录内，静态资源做了目录穿越防护。
  • 配置与 API Key 只落在本机 %USERPROFILE%\.dsh\weekly-report\，写前自动备份、损坏文件另存不静默覆盖。
  • 面板返回的配置里密码一律脱敏；Key 只显示首尾各 4 位。
  • 源工单数据只读；插件不修改研发平台上的任何内容。
  • 不要把数据目录打包分享，里面可能含 API Key、路径与个人信息。
